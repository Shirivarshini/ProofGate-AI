# Member 3 contract-change request: inactive customer enforcement

Status: **pending Member 2 approval; not applied to shared verification documents or schemas.**

## Exact proposed patch

In `docs/VERIFICATION_SPEC.md`, insert after verification step 2:

> Require the authoritative customer record to have `status: ACTIVE`. Any other status is a mandatory `BLOCK` with reason code `CUSTOMER_AUTHORIZATION_FAILED`; it is not eligible for human review.

In the “Always BLOCK” list, add:

> customer status is not `ACTIVE`.

No JSON Schema change is required: `Customer.status` already exists in `docs/DATA_SCHEMAS.md`; this proposal only gives its verification meaning. No API enum changes are required because `CUSTOMER_AUTHORIZATION_FAILED` is already documented.

## Fixture decision

`scn_010` retains `BLOCK` / `CUSTOMER_AUTHORIZATION_FAILED` as an approved fixture expectation. Implementation of this rule belongs to Member 2 and is deferred until this request is approved.
